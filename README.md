# TapTap 制造 · 积分消耗统计

一个 Chrome 扩展，统计 maker.taptap.cn 上账号的积分消耗，并按小时、按天、按项目画折线图。

数据直接从官方接口取，不解析页面 DOM —— 积分页改版也不会失效。所有数据只存在你自己电脑上。

## 安装

1. 浏览器地址栏打开 `chrome://extensions`
2. 右上角打开「开发者模式」
3. 点「加载已解压的扩展程序」，选择本目录（`D:\GameProject\WebExtension`）
4. 先打开一次 `https://maker.taptap.cn` 并保持登录 —— 扩展需要一个已登录的页面来拿到凭证
5. 打开 `https://maker.taptap.cn/credits`，页面右下角会出现一个胶囊，上面直接写着今日消耗

首次打开会自动回填全部历史流水（约 13000 条，翻页读取，1–2 分钟），状态栏会显示进度。之后每 10 分钟自动增量同步一次，也可以随时点状态行旁边的刷新图标。

> **从 1.3.0 及更早版本升级时**，第一次同步会把已有聚合数据清空重建（约半分钟）。这是因为早期版本的增量同步有个 bug、只入库了一条记录，旧数据已经不可信，只能重建。

## 两种打开方式

**页面内的常驻胶囊（默认）** —— 只要你在积分页，右下角就一直有个小胶囊显示今日消耗，不用点任何东西就能看到那个数。点一下滑出完整面板，再点收起。展开状态会记住。

面板**可以拖动左上角调整大小**（它锚在右下角，所以往左上拖是变大）。拖过的尺寸会记住，下次打开还是那么大，并且不会超出窗口。

嗒啦啦模式下她有两种形态，各管一个状态：

**面板收起时**，右下角是她本人加一个气泡 —— 气泡第一行是「今日 N 积分」，第二行是一句随状态变的话，取代原来的胶囊。点气泡展开面板（和原胶囊一样），**点她本人**她会换个表情、换句话，几秒后自己回到状态对应的那个。表情按你**自己的历史**分档（今天相对过去的中位数、p90 落在哪一档），所以花多花少是你跟自己的比较，不是拍死的固定数；同步中和出错也各有一个表情。九个表情来自 `assets/faces.png`。

**面板展开时**，她换成托着面板的姿势（`assets/mascot.png`），气泡收起 —— 面板里已经有数字了，右下角不再摆任何东西。面板为此整体左移了一个她的宽度，让她的左下角正好落在面板的右下角上：素材里伸出的那条手臂在左边缘被裁断，接上竖着的面板边就成了"手伸到面板后面"。

不喜欢她的话，面板标题栏右边有个**嗒啦啦的开关**，拨一下就显示 / 隐藏她（旁边那行字就是她的名字，不随开关变）。**默认开着**，选择会记住。

两种模式在右下角摆什么，是互斥的：**嗒啦啦模式下胶囊一律不出现**（收起时被气泡取代，展开时你不需要它），**普通模式下她一律不出现**（收起展开都还是原来的胶囊）。收起面板靠的是面板自己的 × 按钮，本来就不依赖胶囊。

关掉时她整个不参与布局 —— 面板回到没有她时的落点、不再为她的宽度预留位置，那两张图也都不会去下载。窗口窄于 620px 时同样是这个处理：她自动让位，面板回到普通落点，不会在右边空出一道缺口。

她的高度是 `src/panel.js` 里的 `--mascot-h`（默认 210px），`--mascot-w` 按素材宽高比推出。收起时那个小的只留 `--pet-scale` 一个旋钮（当前 1），她的大小、气泡的内边距/圆角/字号/尾巴全部由它按比例推出来 —— 想整体放大缩小，改那一个数就行（窄窗口用的是同一个旋钮，降到 0.8）。

普通模式下她不在，面板改由 `--plain-r` / `--plain-b` 定位（默认就是最初没有她时的落点）。

**表情合图：** `assets/faces.png` 是一张 3×3 的透明底合图，`src/panel.js` 用 `background-size: 300% 300%` + `background-position: 0/50/100%` 定位到某一格，所以**换图不需要动任何 CSS**，只要还是 3×3、每格里角色位置大致对齐即可。

要换成自己的图，注意两点：底色得抠成透明（原图是带噪点的近白，不是纯白，硬按"白色→透明"抠会留灰边，且要避开角色身上的白色衣物）；九个格子的间距可能不均匀，按 1/3 等分会从角色身上切过去。生成分辨率按最大显示尺寸的 2 倍留即可（现在她显示 108px）。

**位置怎么调：** 由 `src/panel.js` 的 `:host` 里四个变量决定 —— 锚点 `--anchor-r` / `--anchor-b`（她外缘距视口右/下的距离，改这里面板和她一起挪）和相对偏移 `--mascot-dx` / `--mascot-dy`（她相对面板右下角，正数向右/向下）。改完在浏览器里刷新即可看到，数值是像素，试几轮就能对到想要的位置。

面板是在页面里浮出来的，不开新标签页、不打断你正在做的事，也不会挤压或推动站点本身的布局。

**独立的仪表盘页面** —— 点浏览器工具栏上的扩展图标。分析数据时用这个更好：整屏宽度，图表更舒展。

两边看的是同一份数据，互不影响。

## 界面

- **今天** —— 按本地时间逐小时，看一天里什么时候烧分最快
- **近 7 / 30 / 90 天** —— 按天看趋势
- **全部** —— 从有记录的第一天起
- **项目对比** —— 默认画当前时段消耗最高的 7 个项目，每个项目一条线。**这个时段没消耗的项目不会列出来**；有消耗的按消耗量降序排在选择器里，**未勾选的默认折叠**，点末尾的「展开其余 N 个」才铺开
- **放大查看** —— 两张图右上角都有放大按钮，点开是浮层；在里面**滚轮可以缩放时间轴**（以光标所在位置为锚点，滚到最小只剩 3 个点，往回滚就退回全段）。点浮层外或按 Esc 关闭

  在面板里点放大时，浮层是**另起的一层**，原来的面板原地不动 —— 浮层会带着你正在看的图和区间打开，落在同一处。
- **消耗构成** —— 把消耗分成对话 / 图片 / 视频 / 音效·音乐，给出各自金额、占比和一条占比条
- **各类型消耗趋势** —— 上面那几个分类随时间的变化，每个分类一条线
- **明细表** —— 与图表同源，可以逐格核对，也是低对比度配色下的兜底读法

### 为什么是四类而不是三类

接口的 `remark` 里实际会写 **6 种**：对话、生成图片、编辑图片、生成视频、生成音效、生成音乐。

对话 / 图片（生成+编辑）/ 视频 正好三类，但**音效和音乐没有归属**。如果把它们丢掉，类型合计就会小于区间总消耗 —— 那「消耗构成」这张卡片反而不可信了。所以留第四格收容它们。

这一格在真实数据里占比**不到千分之一**，基本可以忽略，但账是平的（音效/音乐确实会产生消耗，只是量极小）。没有消耗时那一格不显示。

> 存储里这个分类的键名仍是 `other`（改它要重建一次数据，而改的只是给人看的标签）。目前落进去的**全部**是音效和音乐；将来接口若新增类型也会落到这里 —— 那时要给它加一条明确的识别规则，不能再叫「音效/音乐」。

分类和项目两套桶是**同一批流水**算出来的，所以类型合计必然等于区间总消耗 —— 这张卡片才敢和上面的数字对照。

状态行右边那个 ↻ 是刷新（只会在同步中转动），不再是一个占地方的大按钮。

时间范围筛选统辖下方全部内容：顶部一行三个指标（区间消耗 / 当前小时 / 活跃项目）、趋势图、平均与最费的指标卡、项目对比，都跟着同一个区间变。

深浅色不单独切换 —— 嵌在站点页面里时跟随站点主题（站点用 `<html class="dark">` 自己管），独立打开仪表盘页时跟随系统。

### 项目对比画哪些项目

默认画**当前时间段内消耗最高的 7 个**，不是历史累计最高的 7 个。切换时间范围时会重算 —— 换一段就该看那一段的头部。一个最近才开工猛烧的项目，历史排名可能很靠后，用历史排名根本进不了默认视图。

选择器里也按本时段消耗降序排列，本时段没消耗的项目直接不出现 —— 列一堆 0 出来只会撑长选择器，还得让人自己一个个排除（鼠标悬停在某一项上仍能看到它在本时段的消耗量）。手动调整只在当前这一屏有效，切走再回来会回到该时段的前 7 高；「重置」也是回到前 7 高。

### 为什么最多勾 8 条

不是配色不够用，是再多就没法保证读得清。

折线取色有一条硬约束：必须按固定顺序**连续分配、不能跳号**——因为「相邻两色可辨」这个保证只对连续取用成立。跳着取（只选第 2 和第 4 个色相）会得到一对没被验证过的颜色，红绿色盲视角下可能糊成一条。整套调色板只有 8 个通过校验的色相，规范也禁止临时造第 9 个。

于是取色规则是：勾中的项目按**本时段消耗排名**依次拿第 1、2、3… 个色相。任意勾选组合都落在已校验的相邻色对上；而且「这段时间烧得最多的那条线」永远是第一个颜色，眼睛第一时间就落在它身上。

代价是：**切换时间范围时颜色会重新分配**（曲线的组成变了）。某个项目在「今天」是蓝色，到「近 30 天」可能变成青色。图例、选择器、悬浮提示都写明项目名，所以认线靠名字，不靠记颜色。

### 已删除的项目

**删除项目不会删除它的历史流水** —— 账本里那些记录还在。所以光看流水永远分不出哪些项目还活着，必须拿 `/api/v1/apps` 返回的「现存项目清单」反过来判定：不在清单里的就是已删除的。

已删除的项目**一律不出现**在选择器和图表里。

要注意的一点：它们的历史消耗**仍然计入**顶部数字和趋势图，只是不在「项目对比」的拆分里。所以那张图的合计会略小于当期的总消耗，差额就是已删除项目花掉的 —— 这部分现在界面上不再提示了。

清单拉取失败时一律当作「未删除」——宁可多显示，不可误藏。

## 数据来源

站点自己的接口，全部带上从页面读到的登录凭证：

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/credits/transactions?from=&limit=` | 积分流水（`limit` 服务端封顶 100，靠 `from` 翻页） |
| `GET /api/v1/credits/info` | 余额与累计值 |
| `GET /api/v1/apps?userId=` | 项目 id → 项目名的映射，同时用来判定哪些项目已被删除 |
| `POST /api/auth/refresh` | 用 refresh_token 续期 |

## 统计口径

流水里的 `type` 字段区分了消耗与获得：

| type | 含义 | 计入消耗 |
| --- | --- | --- |
| **1** | 项目对话 / 生成图片 / 生成视频等消耗 | ✅ |
| 2 | 每小时恢复的额度 | ❌ |
| 7 | 套餐变更等调整 | ❌ |
| 10 / 11 / 14 / 15 / 16 / 20 | 加入活动赠送、套餐发放等 | ❌ |

这条口径是拿全量流水逐条核对过的：**只把 `type === 1` 的 amount 求和，结果与接口返回的 `totalConsumed` 完全一致**。所以赠送的积分、活动发放的额度都不会被算成你的支出。

仪表盘底部会显示本地累计值，可以和积分页的「累计消耗」对照。

## 数据存储

存在浏览器扩展的 `chrome.storage.local` 里，不上传任何地方：

- `daily` —— `{ 日期: { 项目id: 消耗积分 } }`，永久保留
- `hourly` —— 同样的结构再按小时切一层，只保留最近 14 天
- `projects` —— 项目 id 到名称的映射
- `activeProjectIds` —— 当前还在账号里的项目 id，用来反推哪些项目已被删除
- `auth` —— 登录凭证；扩展会用 refresh_token 自动续期
- `sync` —— 同步进度与索引

只存聚合后的桶，不存原始流水。

## 卡在「正在同步」怎么办

先看状态行写的是哪一句：

| 状态行 | 含义 |
| --- | --- |
| 「首次同步中：已读取 N / M 条流水」 | 正常，全量约 1–2 分钟，`N` 在涨就是在干活 |
| 「正在同步新记录…」 | 增量同步，几秒内结束 |
| 「上次同步被中断了，点旁边的 ↻ 重新开始」 | 上一轮被系统回收了，点 ↻ 即可 —— 进度是从断点续的，不会从头再来 |

MV3 的服务进程在长时间同步中被浏览器回收是常态（Chrome 和 Edge 都会）。扩展为此做了四件事，保证它不会变成死锁：

1. **每翻一页都写一次进度** —— 既让「已读取 N / M」真实反映进展，也顺便把服务进程的空闲计时器顶回去（纯 `fetch` 不会重置那个计时器，这是关键）
2. **所有请求带 20 秒超时** —— 卡死的连接会被放弃，不会让整轮同步永远挂着
3. **服务进程一启动就无条件清掉 `running`** —— 进程被杀时来不及跑 `finally`，`running` 会永远停在 true。这里**不看时间**：MV3 同一时刻只有一个服务进程，而进程活着就不会回收挂起中的 Promise，所以「模块顶层代码正在执行」本身就证明了此刻没有任何同步在跑。
4. **三个地方的残骸判断共用 `util.js` 里的 `SYNC_STALE_MS`** —— 判据是 `runningSince` 那个**心跳**时间戳，不是这轮什么时候开始的

第 3、4 条都是踩过坑才补上的，两个坑的成因是同一个：

> 心跳是每翻一页推一次的（第 1 条），所以进程被杀的那一刻它**刚被推新**。早先启动清理是按「心跳超过 5 分钟」判断的，于是残骸要拖满整整 5 分钟才清 —— 这 5 分钟里界面一直显示「正在同步」，手动点 ↻ 也只会拿到 `busy`、什么都不发生。
>
> 与此同时界面那边按 3 分钟判死、后台按 5 分钟拦着，中间那两分钟界面写着「点 ↻ 重新开始」，点下去却毫无反应 —— 这大概是最像「卡死」的一段。

现在改成无条件清（第 3 条），并且 `runSync` 会先等这段清理落盘 —— 否则 `onStartup` / `onInstalled` 紧跟着模块体触发的那次同步，可能赶在清理之前读到旧锁，被自己刚留下的残骸挡掉，白等一个闹钟周期。

## 胶囊上的数字

右下角胶囊的数字**直接按 `daily` 自己算**，后台预算的 `today` 只在对得上日期时才用。这样做是因为它必须和展开面板里的「今日消耗」永远一致 —— 早先只信后台算好的那份，它一旦没写上或写旧了，胶囊就会显示 0，而面板里数字却是对的。

| 胶囊显示 | 含义 |
| --- | --- |
| `今日 57,314 积分` + 绿点 | 正常 |
| `今日 0 积分` + 灰点 | 还没有同步过，点开面板或点工具栏图标开始 |
| `今日 — 积分` + 红点 | 扩展更新过、这个页面还没刷新。**刷新页面即可** |

## 已知限制

- **需要偶尔访问一下 maker.taptap.cn。** access token 只有 2 小时有效期，扩展会自动用 refresh_token 续期；但如果连 refresh_token 也失效了（比如你主动退出登录），就要重新打开站点登录一次。重新打开后扩展会自动接上，不会丢历史数据。
- 小时级明细只留 14 天。再往前就只有日级数据，「今天」视图看不了那么早的小时分布。
- 只统计消耗，不统计余额变化。

## 开发

这个仓库**只放扩展本体**，不含开发脚本（测试、素材生成、预览页都不在里面）。

要改代码，直接改 `src/` 下的文件，在 `chrome://extensions` 里点扩展的「重新加载」即可 —— 没有构建步骤，源文件就是运行文件。改完记得刷新已经打开的积分页：扩展重载后页面上的旧内容脚本会失联，界面上会提示。

## 文件

```
manifest.json          MV3 清单
src/background.js      后台：登录态、翻页同步、增量更新、存储
src/content.js         在站点页面读 localStorage 里的凭证并上报
src/panel.js           页面内的常驻胶囊 + 滑出面板
src/aggregate.js       流水 → 聚合桶（纯函数，可单测）
src/util.js            后台与前端共用的小工具
src/chart.js           手写 SVG 折线图，零依赖
src/dashboard.js       仪表盘的数据组织与渲染
src/dashboard.html     仪表盘结构（?embed=1 时切换成面板内嵌版式）
src/dashboard.css      设计令牌与样式
```

`manifest.json` 只加载 `src/`、`assets/`、`icons/` —— 仓库里除这三处和 README 之外没有别的东西，装进浏览器运行的也只有这些。

### 面板为什么用 Shadow DOM + iframe

`src/panel.js` 不往站点的内容区插节点，而是挂在 `document.body` 上、位置全用 `fixed` 定位。原因：

- 站点是 SPA，内容区由框架托管，插进去的节点可能被它重渲染冲掉
- 直接插入会双向污染样式：站点的样式影响我，我的样式漏到站点
- iframe 里是扩展自己的页面，`chrome.*` 可用，仪表盘那份代码一行都不用改
- 外层 Shadow DOM 隔开站点样式，且完全不依赖站点的 DOM 结构，站点改版也弄不坏

代价是面板和仪表盘之间隔了一层 iframe 边界。目前不需要跨边界通信（关闭按钮在面板这一侧），所以没有影响。
